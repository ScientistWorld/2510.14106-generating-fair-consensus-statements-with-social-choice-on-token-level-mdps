Better results scored higher in the honest comparison, by much more than the seed spread. The gym nevertheless fails the broader scientific-ranking audit: several working shortcuts tie or beat the reference, eight of nine scored metrics are already saturated, and exhaustive optimization solves the entire small test.

The reference-relative rank is zero for the reference. Reported ranks use the specified formula:

`sum_experiments weight * sum_metrics abs(coefficient) * directed(value - reference) / population_std`

Directions and coefficients come from `scoring/reference.json`; reference values come from the fresh reference's evaluator-written `results`, which exactly match the original `scoring/scores_test.json`. Missing metrics contribute zero. The external ranking service is unavailable, so every standardized rank names its normalization cohort. Unless explicitly marked T, the cohort is the ten honest variants listed in `summary.json.quality_cohort`, frozen for every comparison below. Changing that cohort changes numerical ranks. Experiment weight is 1. Zero-coefficient diagnostics do not count; coefficient signs never reverse the declared direction. No units-based scaling or unnormalized weighted sum is used.

The better variant solves a max-min LP for a utility target, then refines with constrained sum-log optimization and independently checks all coalitions using the visible metric. It increases targets progressively and accepts a candidate only when the LP returns alpha exactly 1, stricter than the test's 1e-6 acceptance threshold (the LP itself snaps errors within 1e-8 to 1). It treats all 25 public instances identically. Minimum utility improves in six of twelve test instances, with no decrease in any instance's minimum, and all core metrics remain at their optimum. The aggregate utility gain is 0.001835615636, or 17.465%. This is a genuine improvement to the scored fairness objective; it does not claim greater Nash welfare. Both weaker variants lose clearly. The reproduced method beats its two baselines in the direction reported in paper Section 4.2. Fresh test worst alpha is **1** for Nash, **9.042886737** for uniform and **2,778,272.143273** for utilitarian; baseline violation rates are 0.833333 and 0.75. At rho 1/2/4/8, uniform's worst alphas are 1.6492/2.6144/7.5865/9.0429, and utilitarian's are 2.3271/12.2100/83,581.9214/2,778,272.1433. Nash stays at 1. The synthetic preference formula, normalized Gaussian vectors, path-probability utilities, Nash lottery, conditional prefix masses and proportional-budget coalition LP implement the paper's actual synthetic procedure.

Departures and scope limits relative to the paper:

- The paper's runtime description specifies Frank-Wolfe with a coordinate oracle; the reproduction uses generic SLSQP, up to 2,000 iterations, tolerance 1e-10. It solves the same concave lottery program but does not reproduce that optimization procedure or runtime claim.
- The paper computes conditional masses in a single bottom-up tree pass; `induce_prefix_policy` repeatedly masks/scans the leaf array. The conditional probabilities, including zero actions at unreachable prefixes, follow the paper's definition.
- The executable reproduction covers Section 4.2's B=3, depth=4 synthetic experiment only. It omits the text-generation studies, LLM participant models, EPPL, beam/lookahead search, and token-chunking/scaling experiments. Human consensus quality and practical text-generation efficiency are untested.
- Five agents, dimension 8, rho values 0/1/2/4/8, and seeds 202510–202514 are gym choices; the provided paper text does not specify all these exact choices. The 13/12 even/odd train/test split is also a gym choice and is fully reconstructible from visible train constants.
- Evaluation reads the leaf lottery directly. It neither executes the induced prefix policy nor verifies that a submitted policy generates that lottery. It scores minimum expected probability utility, rather than the EPPL used in the paper's text experiments. There is no scored runtime or compute constraint.

The brute-force result is material: [honest_exhaustive_optimizer](redteam/honest_exhaustive_optimizer/run.sh) enumerates all **81** leaves and solves a generic full-dimensional lottery program, without constructing or executing a token policy. It solves the test and ties the reference within noise. This is an **honest alternative the test cannot tell apart**, not evidence of a better generation method. Enumerating just the best single leaf fails, as the table shows. Exhaustive lottery optimization is cheap here, so this test is too small to assess the tractability motivation for chunking or restricted search. The paper's own Section 4.2 deliberately uses this small space; the limitation is using it as the whole improvement benchmark.

The missing-coverage shortcuts use the visible complete grid and cached public outputs, without reading hidden scores or hidden fixtures. In `shortcut_easy_instances`, the omitted test cases are rho=1 seeds 202510 and 202514. Baseline entries keep all twelve required records present, so checking record coverage alone does not help. Its full metric vector matches the genuine improvement. `shortcut_grid_replay` requires the reference implementation available in improve mode; omission, empty-output and generator-replacement shortcuts also apply from scratch. This is a fixed public instance split, rather than genuinely unseen preferences.

`shortcut_filter_methods` demonstrates that the hidden test does **not** write every submitted method under `results`. It takes its output whitelist from agent-editable `scoring/scores_train.json`, despite already evaluating the omitted method internally. This shortcut suppresses a weak method while retaining a reference tie; it does not turn that weak method into a stronger result.

For the four invalid shortcuts, the evaluator exits before its final write and leaves the deliberately prefilled score file byte-for-byte unchanged. These files are retained in their folders for evidence and are explicitly **excluded** from successful-score calculations. A failed run does **not** receive worst values in every scored metric. That is a failure-handling defect, even though no successful test-written shortcut score was obtained from these four runs. In contrast, empty policy lists produce a successful newly written empty result, so all penalties disappear under the stated missing-value rule.

T is an admissible cohort of three actually evaluated attempts: `shortcut_constraint_tradeoff_a`, `shortcut_constraint_tradeoff_b`, and the honest `better_core_fairness`. The fixed reference remains the comparison point and is not included as a future attempt when computing their variation. These variants have almost identical minimum utilities: their population standard deviation is **1.498773891e-6**. Their utility gains over the older reference therefore contribute +183.528019 and +183.344307 respectively, outweighing all core penalties. A's worst alpha is 7.586489261 and B's is 9.042886737; both fail core stability on 10/12 instances, yet both outrank the reference in T. Every nonzero-coefficient metric has nonzero variance in T, so this counterexample needs no zero-variance convention. It establishes that the sum is not a reliable constraint: a failing method **can** outrank the reference through its other metrics. It does not assert that these shortcuts win in every cohort; they lose under the diverse honest cohort used for the main table.

The zero-coefficient diagnostics are also at their best values: simplex error=0 and rho=0 alpha=1. The only unsaturated scored metric is minimum utility, initially 0.010510063376. A strong simple baseline remains clearly below the reference on core stability, but the reference has no room to improve its main scientific criterion. `reference.json` declares the utility metric and coefficient but omits its numeric proposed-method value; the actual reference test scores supply it here.

The most consequential next-iteration fixes are to require every method on every instance with a complete metric schema; write explicit worst-value results for failures; derive required methods independently of editable train scores; protect the reference preference generator as evaluation ground truth; and enforce core stability before aggregating utility gains. Strict simplex validation and execution of the submitted token policy would close the invalid-mass and unused-policy shortcuts. Unseen preference draws and a larger or explicitly constrained outcome space are needed to distinguish general methods from fixed-grid replay and exhaustive optimization. Restoring a hard constraint is more reliable than increasing its coefficient, because normalization over future attempts changes the exchange rate.
